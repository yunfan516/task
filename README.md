# 选题 58：内部排序算法可视化与性能对比平台

## 项目简介

本项目为《数据结构》课程设计（选题 58）。八种内部排序算法全部由 C 语言（`sort_core.c`）实现，并通过 Zig 编译为 WebAssembly 模块 `sort_core.wasm`，统一入口为 `void sort(int a[], int n)`（配合 `set_algorithm` 选择具体算法）。网页前端（HTML / CSS / JavaScript）仅负责界面展示与调用 WASM，不另行实现排序算法。

## 项目核心功能

- 在 `sort_core.c` 中实现 **8 种内部排序算法**：直接插入、折半插入、希尔、冒泡、快速、简单选择、堆排序、归并排序。
- 统一 `void sort(int a[], int n)` 调用入口与算法编号选择，覆盖空输入、单元素、非法编号与大规模边界检查（基准规模 `1,000 ~ 100,000`，动画上限 `n ≤ 50`）。
- 统计关键字比较次数、元素移动次数与纯算法高精度耗时，并基于 `Record { key, id }` 结构验证相同关键字的稳定性。
- 提供网页交互界面（`index.html`）与 Web Worker 后台 `8×4` 基准对比（`benchmark-worker.js`），支持随机、正序、逆序、大量重复键四类分布及随时停止。
- 提供 `tests/test-cases.mjs` 自动化测试脚本（覆盖 `T1~T8` 共 8 类测试）与 `tests/benchmark-record.md` 多规模实测记录。

## 统计口径说明

- **比较次数（`COUNT_CMP`）**：仅统计算法对排序关键字 `key` 执行的比较，不包含循环下标边界比较。
- **移动次数（`COUNT_MOV`）**：统一统计元素赋值写入（含临时变量提取、交换写回与归并辅助数组写回）。
- **纯算法耗时**：C 核心通过宿主注入的 `high_res_time()` 仅包裹纯排序执行区间，剥离前端动画重绘开销。
- **同源副本控制**：基准对比对每类分布先生成单份母本数组，再深拷贝给八种算法独立测试。
- **稳定性验证**：构造 32 条重复键记录 `(key = i % 3, id = i)`，排序后若存在相等 `key` 下 `id` 逆序递减即判定为不稳定。

## 自动化测试套件（`T1~T8`）

```powershell
node tests/test-cases.mjs 100000
node tests/test-cases.mjs --multi
```

| 编号 | 测试内容 | 判定依据 |
|---|---|---|
| T1 | 同一数组八种算法排序 | 八份输出数组严格升序且逐元素完全一致 |
| T2 | 正序输入下的冒泡与快排 | 冒泡提前终止比较恰为 `n-1`；快排比较处于 `n·log2n` 量级 |
| T3 | 逆序与全相同输入下的快排 | 三数取中防退化生效，无栈溢出，比较次数远小于 `O(n²)` |
| T4 | 含相同关键字的记录排序 | C 核心判定、按 `(key, id)` 序列复核与理论稳定性三方一致 |
| T5 | 空数组与单元素极小边界 | `n=0` 与 `n=1` 下八种算法均安全返回且无越界 |
| T6 | 规模越界与非法算法号拦截 | `n<0`、`n>100000` 及 `alg∉[0..7]` 均返回 `-1` |
| T7 | 状态快照帧数与规模门控 | `n=50` 逆序产生精确帧数（`51/72/205/1227`），`n=51` 自动阻断为 `0` 帧 |
| T8 | 多随机种子跨样本复现核验 | 更换 3 组独立种子后八算法一致性、折半减比较不减移动及量级规律恒成立 |

## 自主增强：步骤快照与可控回放

- **6 维回放控制**：支持播放、暂停、上一步、下一步、重置、速度调节与进度条任意跳转（可视化规模门控 `n ≤ 50`）。
- **C 源码同步高亮**：步进回放时同步高亮 `sort_core.c` 当前执行代码行，并实时联动比较次数与移动次数。
- **改前 / 改后 / 代价实测（`n=50` 逆序）**：
  - **改前**：回放控制项 `0` 个，仅黑盒输出排序结果；冒泡纯排序耗时 `0.0039 ms`，快照额外空间 `0 B`。
  - **改后**：提供 `6` 类回放控制；直插 / 折半 / 选择 / 堆 / 归并生成 `51` 帧、快排 `72` 帧、希尔 `205` 帧、冒泡 `1,227` 帧。
  - **代价**：快照空间复杂度 `O(F×n)`，约 `20 KB`（51 帧）至 `479 KB`（冒泡 1,227 帧），冒泡开启回调耗时升至 `3.0343 ms`；大规模基准测试自动关闭快照。

## 算法复杂度与稳定性参考

| 算法 | 平均时间 | 最坏时间 | 额外空间 | 稳定性 |
|---|---|---|---|---|
| 直接插入 | `O(n²)` | `O(n²)` | `O(1)` | 稳定 |
| 折半插入 | `O(n²)` | `O(n²)` | `O(1)` | 稳定 |
| 希尔排序 | 依赖增量序列 | `O(n²)` | `O(1)` | 不稳定 |
| 冒泡排序 | `O(n²)` | `O(n²)` | `O(1)` | 稳定 |
| 快速排序 | `O(n log n)` | `O(n²)` | `O(log n)` | 不稳定 |
| 简单选择 | `O(n²)` | `O(n²)` | `O(1)` | 不稳定 |
| 堆排序 | `O(n log n)` | `O(n log n)` | `O(1)` | 不稳定 |
| 归并排序 | `O(n log n)` | `O(n log n)` | `O(n)` | 稳定 |

## 本地运行与构建说明

网页通过 `fetch` 加载 `sort_core.wasm`，请使用本地静态服务器启动（不能直接用 `file://` 打开）：

```powershell
npx --yes http-server . -p 4173
```

启动后访问 `http://localhost:4173`。仓库已内置编译好的 `sort_core.wasm`；如需从 `sort_core.c` 重新构建，可执行 `build.bat`（需安装 Zig）：

```powershell
zig cc -target wasm32-freestanding -O2 -nostdlib sort_core.c -Wl,--no-entry -Wl,--export-memory -Wl,--initial-memory=16777216 -Wl,--max-memory=16777216 -Wl,--strip-all -o sort_core.wasm
```

## 答辩演示与验收流程

1. **启动服务**：执行 `npx --yes http-server . -p 4173`，浏览器打开 `http://localhost:4173`，确认 WASM 模块加载就绪。
2. **步进回放与源码联动**：选择冒泡排序或快速排序（`n ≤ 50`），演示播放、暂停、上一步回退、进度条跳转、倍速调节及右侧 `sort_core.c` 行同步高亮。
3. **边界输入与稳定性核验**：输入正序、逆序或含重复元素的自定义序列，查看比较次数、移动次数、C 平均纯耗时与稳定性实测标签。
4. **多规模矩阵压测与 CLI 复核**：在页面启动 `1,000 ~ 100,000` 规模的 `8×4` 性能对比（支持后台进度刷新与随时停止），并在终端运行 `node tests/test-cases.mjs 100000` 验证 `T1~T8` 全量通过。
